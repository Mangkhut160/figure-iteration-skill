# 交付与沟通

这里是默认做法；用户另有习惯或要求时：个人习惯记进用户的记忆，这篇论文特有的要求记进 profile 的「语言与沟通」，以记下的为准。

## 1. 每一轮的回复

- 第一句说交了哪些文件，给出交付目录里的文件路径（完整路径还是相对路径，按 profile 的「语言与沟通」），做成链接。
- 改了什么，写两三条；哪些地方是按我的理解做的（请他确认）；请他在自己的编辑软件里看哪里。
- 给前后对照图的链接；检查结果用一句话说。
- 没做或做不了的，直接说，并给出下一步。
- 不贴长表格，不复述文件的内容。

## 2. 提问

- 一次最多问三个问题，每个写成「我的理解 + 另一种可能」；能从材料里推出来的不问。写在文件里给他看的东西（brief 里的待确认假设、资料清单、图标清单）不算在这三个里：他不改就按默认走。
- 位置的说法有歧义（如「把 X 放到左上角」）：列出两三种理解问他，或者按最像的放并标出来。
- 程度的说法没给数（「再大一点」「往左挪一点」）：做小幅度的调整（幅度的默认值可以在 profile 里定），和它相关的那一边或中心不动（贴着线的那边、对齐的那边），在回复里写出改前改后的数，请他说还要不要再调。
- 用户常常不在聊天里回答，而是直接改文件。所以下一轮先对比他保存的文件（`pptx_user_edits.py`），按他改的算。
- 他点名了位置，就照做。我觉得别的地方更好，可以提出来，但先按他说的做。
- 不擅自做大的改动（例如把手改并回脚本、加新节点）：先提出来，他同意了再做。

## 3. 解释和清单写成单独的 md

用户要解释（如某个符号的含义）、要清单（如还缺哪些数据），或者说「整理到 md 里」时：

- 每个问题写一个文件，放在交付目录（路径见 profile 的「文件放哪」）。文件名用 ASCII、带图号（如 `figN_todo_data.md`），这样链接点得开。要他填的表（资料清单、填数表）也一样放这里。
- 自成一篇：开头说明对应哪一版、各个符号是什么意思；不写「见上文」；需要出处的写路径和行号。
- 聊天里只给链接和一两句话，不要把同样的内容在聊天里再写一遍。

## 4. 语言和署名

- 交流和图上的字用什么语言，按 profile 的「语言与沟通」。
- 聊天里要不要给完整的本地路径，也按 profile；图、图注、论文正文、交付的 PDF 和 PPTX 里不露本地路径和私人文件名。
- 写给别人看的东西（图注、文档）按读者来写；交付物里要不要署工具或 AI 的名字，按 profile 的「硬规则」（默认不署）。

## 5. 每一轮都记下来

用户这一轮做的决定（选了哪个位置、哪种口径），写进 brief 的 §6x（`content-sync.md` §3）和图目录的 `iteration-history.md`。以后还会用到的偏好和规则，写进记忆；属于这篇论文的，写进 profile。
