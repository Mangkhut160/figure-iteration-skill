# 出图与检查

## 1. 出图

- 迭代时 `make_from_saved.sh` 已经全做了。单独跑：`python $SK/scripts/render_pptx.py <pptx> <输出名> [--before <旧 pptx>] [--thumbnail] [--dpi 300]`。
- 用 LibreOffice 代替用户的编辑软件（WPS、PowerPoint 等）渲染：先复制到临时目录再转，每次用临时的用户配置（`-env:UserInstallation`）；无损、不降采样，PDF 的元数据清空。它能暴露结构和形状上的真问题，暴露不了编辑软件自己的渲染差别。
- 交哪个 PDF：出初稿阶段 SVG 是主文件，交 Chromium 从 SVG 导出的 `fig.final.pdf`；pptx 成为主文件以后，交这里从 pptx 渲出的 `fig.vN.pdf`。不必每轮都去换论文里引用的那个 PDF：要编译论文看效果、或者定稿时，再把最新的复制成 LaTeX 片段引用的文件名（或改片段里的路径）。

## 2. 自动检查（`audit_outputs.py`）

| 检查 | 标准 | 不过时多半是 |
|---|---|---|
| 页面 | 一页；尺寸等于 `FIG_PAGE`（`--page`，误差 0.3 pt 以内）；没设就不查 | 有形状出了页面，或页面尺寸被改了；SVG 路线里画布宽不是 0.75 pt 的整数倍，Chromium 取整造成的 |
| 字体 | 没有 Type 3（多数投稿系统会拒，以 profile 为准）；每个字体都嵌入；TrueType、Type0 都可以 | 查是哪个字体，换掉 |
| 字号 | 只有 `FIG_SIZES`（`--sizes`）里的；没设就只列出来，不查 | 新加的文字没有从现有文本框复制 |
| 位图 | 每张印刷后不低于 300 ppi | 换更大的源图，或把图缩小 |
| 文件大小 | 不超过 `FIG_MAX_MB`（`--max-mb`）；没设就不查 | 位图太大 |
| 署名和用户名 | 文件里没有流水线留下的痕迹（figgenie、「generated by/with/using」、「AI-generated」）、本机用户名、底稿里编辑软件写的账号名（`--forbid-authors-of`）、`FIG_FORBID` 给的词（profile 要求时，把 AI 产品、公司、工具、机构的名字写进去，逗号分隔） | 看上下文：图里本来就有的英文单词也可能命中 |
| 作者字段 | pptx 的 creator 和 lastModifiedBy 为空；app.xml 的 Company 和 Manager 为空 | 补丁没有用 `K.save` 保存 |
| PDF 元数据 | 打印出来；非空时警告（不算失败） | Chromium 导出的 PDF 带 Creator / Producer：`pdf_clean.py` 清空（`make_draft.sh` 已经做了） |
| PNG | 文本块里没有署名 | — |

- 出初稿阶段另有：figgenie 的 `check.py`（lint）、`latex_check.py`（公式出框、压字）、`pdf_text_width_check.py`（字距）、`pptx_check.py`（svg2pptx 有没有丢东西）。
- 新版的 nature-figure 还带 SVG、PDF 文字、碰撞三个审查脚本：装的版本里有就一起跑，没有就用上面这些代替。

已知的误报：
- `pdf_text_width_check.py`：旋转的文字（如竖排的标签）比的是横向包围盒，会报成大偏差。
- 碰撞审查（nature-figure 新版的脚本）：它读 PDF 的几何，不管谁盖住谁，所以被白底盖住的框线也会报 FAIL。先看 overlay 和放大图再判断真假。
- LibreOffice 打印的 "Could not find platform independent libraries" 无害。

## 3. 亲眼看

检查全过不等于图没问题。每一轮都看：

1. 100% 大小的 PNG（例：300 pt 宽、300 dpi 是 1250 px）。
2. 前后对照图：只有这一轮要改的地方变了，用户的手改都还在。
3. 每处改动放大 3 倍看（用 PIL 裁到临时文件，看完删掉）：字有没有出框、压线；新元素和旁边的东西对齐了没有（边缘差 0.3–2 pt 最显眼）；箭头是否接在 profile 规定的位置；间距和旁边是否一致。
4. 灰度与色弱图：profile 里写的色义在灰度和红绿色弱下还分得开；不能只靠颜色表意。
5. 印刷尺寸下读得清：最小字号（`FIG_SIZES` 里最小的一个）是下限。

看到问题就改补丁，用 `--redo` 重跑，再看一遍。

## 4. 回复里的证据

回复里给出检查的结论和关键的数（例：「检查全过：字号都在允许的范围内，位图最低 400 ppi，作者字段已清空」），并说明放大看过哪些地方。没跑的检查、没看的地方，直接说。
