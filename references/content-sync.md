# 内容核对与文字同步

## 1. claims_vs_code.md

图上的每个框、每条边、每个图标、每个示例数，都要对到代码和成立条件。格式：

| 图上的元素 | 图上的说法 | 代码依据（文件:行） | 成立条件 | 状态 |
|---|---|---|---|---|

- 状态分六种：成立；简化（图比代码少画了什么，要写出来）；待定（取决于还没定的设计）；装饰（不对应数据流，写明它不说什么）；占位；待溯源（用户给的数或说法，出处还没补上）。
- 代码不在手边时，核不到的行标「待核」，到有代码的仓库里补核。
- 每一版新加或改了说法的元素，加一节「vN …」，不改旧的小节；旧节里被撤回的，标「vN 撤回」。
- 行号注明是哪天读到的；路径相对代码仓库的根目录。
- 图标也要写它说什么、不说什么（例：一个「齿轮」图标暗示「可配置」，而这个模块没有可配置项，就不放它）。
- 示例数字写「示意，不是某一次实验的记录」，并给出量级的依据（单位、误差大小）。

## 2. 图注和 LaTeX 片段

- `caption.md`（英文图注、每版的改动说明、署名句、核对要点）和放进论文的 LaTeX 片段（文件名写在 profile 里），两处的图注逐字一致。
- 图上的字改了（标签、符号、例子数字），图注同一轮跟着改；图注里的符号要和图上的 LaTeX 一致（`$x_t$`、`$\hat{y}$` 这类）。
- 图上删掉的信息如果只剩图注里有（例如某些名字只在图注的括号里），在改动说明里标出来（例如「别删」），免得以后被当成多余的删掉。
- 署名句：引用键要在论文的 .bib 里存在；字面占位（如 `[Name]`）留给用户填。
- 匿名规则、用词规则（哪些词不写、术语和正文一致、能识别作者的内容）以 profile 的「硬规则」和「图注与用词」为准。
- LaTeX 片段里引用的 PDF 文件名：不必每轮都换；编译论文看效果或定稿时，指向最新一版（或者把最新的 PDF 复制成那个文件名），见 `render-and-audit.md` §1。

## 3. brief.md 和其他记录

- §6 是待确认的假设（figgenie 简报模板里的那一节）：还没定的留在那里，定了的写上结论和日期。
- 每一版在 §6 后面加一小节（§6b、§6c……，下面的「§6x」就指它）：用户的原话、底稿是哪一份（保存时间）、他手改了什么、我做了什么、哪些是按我的理解做的（等他确认）。
- 同步图目录里记着「最新版是哪一版、文件在哪」的说明文件，和交接包的入口文件（如果有）。
- 每一版在图目录的 `iteration-history.md` 里加一行：用户的要求、做法、留下的规则。
- 新素材记进 `assets/SOURCES.md`。

## 4. 数字一致

- 图上的结果数、摘要和引言里的数、表格里的数，三处必须一致（正文里数字占位用的宏写在 profile 里）。不一致先问用户，不自己挑一个。
- 图上的数没冻结就占位（`references/data-panel.md`）。
