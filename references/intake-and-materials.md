# 开始前：接手、向用户要资料、提取

## 1. 接手

- 交接包（如果有）：先读它的入口文件，再读图目录里自带的说明文件（如 `README.md`、`WORKFLOW.md`，有的话，里面常写着最新版是哪一版）、`brief.md`（尤其 §6 的待确认假设和每版的改动记录）、`claims_vs_code.md`、`caption.md`、`iteration-history.md`。
- 最新版以交付目录里的文件为准，不以脚本版为准：`python $SK/scripts/latest_saved.py <交付目录>`。
- 读用户的记忆和这篇论文的 profile（找法见 SKILL.md；没有就先做 `references/new-paper.md`），了解以前定过什么。

## 2. 一次把资料要齐

写完 brief、交给用户确认时，就把下面这些一次要齐，不要画到一半再分批要。可以把 `$SK/templates/materials_request.md` 改成这张图的版本发给用户。

| 类 | 要什么 | 用来做什么 |
|---|---|---|
| 内容 | 图要说的一句话（我先写，用户改）；对应的论文段落和代码位置；还没定的设计 | 写 brief 和 `claims_vs_code.md`；没定的先画成中性标签。代码不在手边时：到有它的仓库里核对，或请用户把相关文件放进资料文件夹；核不到的行标「待核」，并告诉用户 |
| 数字 | 每个数从哪来（实验记录里的条目或结果文件） | 结果小图；没冻结就占位 |
| 图标 | 每个要画成图标的概念各一个文件（PNG ≥512 px 透明底，或 SVG） | 见 §3 的图标清单 |
| 照片和截图 | 实验装置、场景、示例输入输出 | 抠图，裁成统一比例 |
| 标志 | 第三方的标志（品牌、模型、数据集）的 SVG | 保持矢量，或转成高分辨率 PNG |
| 参考论文 | arXiv 编号，或下载好的源码包 | 切图；借画法 |
| 风格 | 从候选参考图里挑 2–4 张 | 版式、密度、配色的偏好 |
| 版面 | 单栏还是通栏、高度上限、交付到哪个文件夹 | 画布大小、检查参数（`figure.env`） |

许可：第三方图片的许可由用户负责。按 profile 里的约定办；没有约定就问一次，把答案记进 profile，之后不再问。我只把出处记进 `assets/SOURCES.md`，留一栏许可给他填。

放哪：要用户填的资料清单写成单独的 md，放在交付目录，名字带图号（如 `fig2_materials.md`）；brief 和参考图拼图留在图目录，聊天里给能点开的链接。清单和 brief 里的待确认假设是写在文件里给他看的；聊天里要他当场回答的问题，最多三个（`communication.md` §2）。

## 3. 图标清单

brief 写完后，按组件列一张表发给用户：

| 图里的概念 | 我建议的图标 | 用户给的文件 | 放在哪 | 颜色 |
|---|---|---|---|---|
| <概念 A> | <建议的图标> | | <位置> | 原色 |
| <概念 B> | <建议的图标> | | <位置> | 按角色改色 |

- 用户给了文件、写明了位置的，照做。位置的说法有歧义（如「把 X 放到左上角」）时，列出两三种理解问他，或者按最像的放并标明是按哪种理解放的。
- 图标只放在图里有对应元素的地方。如果一个图标会让人读出图上没有的意思，就不放，并说明理由（例：一个「锁」图标放在还没定的中性标签上，会被读成这个标签是加密的）。
- 用户没给文件的概念，问他要不要我画。画的存成 `assets/icons/<名>.svg` 和 `.png`，出处表写「自绘」；用户以后给了文件就换掉。
- 用户说「图标你看着办」：先用他已经给过的和 `assets/` 里现成的；缺的从 figgenie 部件库的 `original` 部件里找，或者自己画。默认不自己上网下载第三方图标（许可要用户把关；profile 另有约定的除外）；真需要的，列出来请他下载。图标清单照样发给他看，作为通知，不算提问。
- 模块里的图标按图例改色（具体的色义看 profile）；表示事物或动作的图标保留原色。用户要原色就不改。

## 4. 提取（用户的文件夹只读，结果写进 `<图目录>/assets/`）

用系统 Python（需要 PyMuPDF、Pillow、numpy）：

```bash
X="python $SK/scripts/extract_assets.py"
$X pdf-images <源码包>/figures/teaser.pdf <临时目录>       # 导出 PDF 里所有内嵌位图（软蒙版合成透明），逐张看后挑
$X cutout <挑出的那张> assets/photos/device.png --max-h 340  # 去白底，裁到边缘
$X icon <图标集>/a.png assets/icons/a.png         # 裁边，缩到 256 px（预乘透明，边缘不发黑）
$X tint assets/icons/a.png assets/icons/a_grey.png --dark '#555555'   # 按角色改色，明暗层次保留
$X glyph <浅色底的黑线稿> assets/icons/b.png                 # 变成纯黑加透明
$X svg assets/icons/mark.svg assets/icons/mark.png            # 自绘图标或标志的 SVG → 透明 PNG
```

- arXiv 源码包：`curl -sL -A "Mozilla/5.0" "https://arxiv.org/e-print/<编号>" -o src.bin`，再 `tar -xzf src.bin -C <目录>`。架构图大多是矢量 PDF：只借画法，画进自己的 SVG，不拷图形。里面嵌的位图（照片、抠图、图标）才切出来用。
- 照片裁成统一比例（例如同一类的照片都用同一个宽高比），印刷尺寸下不低于 300 ppi（`audit_outputs.py` 会查）。
- 抠不干净的（例如照片里连着背景物品），要按颜色去掉，再手工划掉残影。这类一次性处理写在图目录的 `tools/prep_assets.py` 里，可以重跑。
- figgenie 部件库：标为 `provenance: original` 的部件可以直接用，标为 `corpus` 的只作风格参考。
- 每个文件在 `assets/SOURCES.md` 记一行：文件、内容、来源（论文的 arXiv 编号和源文件路径，或用户文件夹里的原文件名）、怎么处理的、放在图里哪里，许可一栏留空。不再用的标「vN 起不用」，记录不删。

## 5. 资料放哪

- 用户下载的原始资料：放在交付目录旁边的文件夹里（路径写在 profile 的「文件放哪」），只读。
- 处理过的：`<图目录>/assets/`（`photos/`、`icons/` 等），由脚本生成，可以重跑。
